From changelog to merged PR.

Nobody reads changelogs. Driftless reads the spec instead, and only speaks up when your code is actually affected.

01 · DETECTProvider webhook

The API provider publishes a new spec. Driftless diffs it with rules, not guesses: renamed fields, moved endpoints, new required params.

02 · SCANAffected calls only

Parses your code and maps each change to the exact functions that use it. No impact, no noise.

03 · PATCHScoped fix

Edits only inside the affected functions. A range guard rejects any patch that reaches further.

04 · PROVERed → green, then PR

Runs your tests against the new API. Passing patch becomes a PR. Anything else becomes an issue with the reason.

Built to be trusted with your codebase.

You give a tool access to your repo only if it is careful. These are the rules it follows.

What it can do
  • Read your repo and open branches and PRs. Never pushes to main.
  • Patch only affected functions. Out-of-range edits are rejected.
  • Open a PR only when tests pass against the new API version.
What it won't do
  • Never guesses when a field is removed with no replacement. It opens an issue.
  • Never merges. A human reviews every change.
  • Never sends your code anywhere in this build. Patches are deterministic codemods run locally.
