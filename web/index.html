How it works

Source → detect → fix → alert.

Nobody reads changelogs. Driftless reads the spec and the page itself, and only moves when your code is affected.

1
API spec or web page

OpenAPI specs are compared by endpoint; web pages are crawled and compared by text.

2
Detect, then Jev judges

Checked on a schedule; changed lines go to Jev, a decision model. Noise is dropped silently; only breaking changes move on.

3
AI fixes the code

Claude patches the affected code and writes the PR. It must pass the range guard and your tests.

4
Slack · Email · PR

Changes go to Slack and email; fixes arrive as GitHub PRs. A human merges.

AI-powered monitoring

One AI judges. Another writes. Your tests decide.

The AI that writes the fix should never grade its own work. A non-generative model judges, a generative model writes, and your tests have the final say.

J
Jev · the judge

A non-generative decision model by TypeSafe. It never writes text; it returns typed answers with probabilities: "meaningful 0.85 · breaking 0.97 · kind: breaking".

C
Claude · the writer

A generative model. Only when Jev says it's breaking, Claude writes the patch for the affected code and the PR description.

T
Your tests · ground truth

Before the patch the tests must fail against the new API, after it they must pass. No AI overrides the tests.

1 · Diff the contract, not the changelog

Every field has a stable identity. Same identity, new name means renamed. Identity gone means removed.

- "status": { "canon": "status" }
+ "state":  { "canon": "status" }   → renamed
2 · Find the exact call sites

Only functions that call the changed endpoint with the same HTTP method are affected.

shop_client.py:17  create_charge()  POST /v1/charges
shop_client.py:22  charge_status()  GET  /v1/charges/{id}
3 · Claude patches, the guard checks

Any edit outside the affected functions is rejected and replaced by a rule-based patch.

-  r = _call("POST", "/v1/charges", ...)
+  r = _call("POST", "/v2/payments", ...)
4 · Prove it before anyone sees it

main must fail (the break is real) and the patched copy must pass.

main     vs v2  FAILED (errors=2)
patched  vs v2  OK  → PR #1

Security

Built to be trusted with your code.

What it can do
  • It can read your repo and open branches and PRs. Never writes to main.
  • It patches only affected functions.
  • It opens a PR only when tests pass.
What it won't do
  • Never guesses when a field is removed with no replacement.
  • Never merges. AI agents can't merge either.
  • Never trusts AI output blindly. Only the affected file goes to Claude; the range guard and tests decide.
