Self-Maintaining APIs 흐름

검증을 통과하지 못하면 PR을 열지 않는다. 초록은 통과, 빨강은 중단.

1. 전체 흐름 (게이트가 곧 정확도)

flowchart TD
  A["제공자가 스펙 v2 배포"] --> B["① Diff 엔진 (규칙 기반, LLM 아님)"]
  B -->|"깨지는 변경 목록"| C{"영향받는 호출이 있나?"}
  C -->|"없음"| Z["아무것도 하지 않는다"]
  C -->|"있음"| D["③ Scanner: 호출 위치 추출"]
  D -->|"영향받는 스니펫만"| E["비밀키 필터"]
  E --> F["④ Patcher (LLM): 수정안 생성"]
  F --> G{"허용 범위 안의 diff인가?"}
  G -->|"아니오"| X["거부"]

2. 시간 순서 (90초 데모 장면)

sequenceDiagram
  autonumber
  participant P as 제공자 스펙
  participant E as 엔진
  participant R as 고객 저장소
  participant L as LLM
  participant M as mock 서버
  P->>E: v2 공개 (스펙 변경 3건)
  E->>E: 스펙 비교, 깨지는 변경 분류
  E->>R: 읽기 전용으로 호출 위치 검색
  R-->>E: 영향받는 스니펫 3곳
  E->>L: 스니펫 + 변경 내용만 전송
  L-->>E: 수정안
  E->>M: v2 mock에 대해 테스트 실행
  M-->>E: 패치 전 실패 / 패치 후 통과
  E->>R: 브랜치 생성, PR 열기 (근거와 전후 결과 포함)
  Note over E,R: 1건은 검증 실패, PR 없이 이슈만 열림
